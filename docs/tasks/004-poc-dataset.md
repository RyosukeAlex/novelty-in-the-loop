# Task 004: POC データセットの実装要件

**担当：りけ（実装）／ Claude（要件・レビュー）**
要件確定日：2026-10-25

## 目的

検証①②（`docs/pilot.md`）を小規模で回し、配管と予備結果を得るためのデータセットを切り出す。
研究目的（AI Scientist の新規性判定の改善）と母集団を整合させる。

## 決定事項（2026-10-25、りけの判断）

| 論点 | 決定 |
|---|---|
| POC の規模 | **段階的に両方**。まず数百本で配管、次に本数を増やして予備結果 |
| 絞り込みの主軸 | **arXiv 中心**（AI Scientist の出力＝論文草稿と形式が一致するため） |
| 母集団の性質 | **両方作って比較**。preprint 群（査読前）と article 群（査読済み）の2群 |

## 1. ⚠️ 要件に対する修正：埋め込み走査は段階化できない

「まず 1〜2 ファイルだけ走査して配管を確認する」は**成立しない**。

埋め込みファイルの `paperid` はソートされていない（`docs/tasks/003-embedding-extraction.md` §1）。
1 ファイルは全体の 0.9% にすぎず、POC 対象の数百本のうち拾えるのは数本。
しかも**その数本の参考文献・被引用が同じファイルに入っている確率も 0.9%** なので、
過去ベクトルも未来ベクトルも作れない。

> **走査コストは対象リストの大きさに依存しない。** 1.62TiB を読む時間だけで決まるので、
> 対象が 500 本でも 50 万本でも同じ $1 未満。**最初から 499,727 件すべてを 1 回で取る。**

段階化は**分析側でのみ有効**にする。

| 段階 | 埋め込み | 分析対象 | 目的 |
|---|---|---|---|
| 0 | 取得しない（ランダムベクトルで代用） | 数十本 | ベクトル計算・指標算出のコードが動くか |
| 1 | **全 499,727 件を 1 回で取得** | 各群 300 本 | 実データで配管を通す。数値の妥当性を目で確認 |
| 2 | 同じデータを使う | 全 9,857 本 | 検証①②の予備結果 |

段階 0 をランダムベクトルで先にやれば、走査の前にコードのバグを潰せる。
なお「1 ファイル目で止めて課金を確認する」は**リージョン未確認リスクへの対策**として別途必要
（`docs/tasks/003-embedding-extraction.md` §3）。これは段階化とは別の話。

## 2. 確定した事実（2026-10-25 実測）

### 2-1. 分野 ID では AI Scientist の対象領域に絞れない

`sciscinet_fields` は **level 0（19件）と level 1（284件）のみ**。
「deep learning」「言語モデル」「拡散モデル」といった粒度は存在せず、
**Machine learning（`C119857082`）が最下層**。

> AI Scientist v1 のテンプレート（nanoGPT・2D diffusion・grokking）に対応する分野タグは取れない。
> 絞り込みは **媒体・`doctype`・被引用**の組み合わせで行う。

### 2-2. 対象論文の掲載媒体（上位のみ）

| 媒体 | 本数 | うち preprint | 平均被引用 |
|---|---:|---:|---:|
| **arXiv** | **5,211** | 4,879 | 41.9 |
| AAAI | 228 | 0 | 94.0 |
| NeurIPS | 171 | 0 | 105.9 |
| ICML | 96 | 0 | 94.9 |
| ICLR | 65 | 0 | 138.5 |
| EMNLP | 64 | 3 | 115.3 |
| bioRxiv | 216 | 216 | 10.6 |
| Indian Journal of Science and Technology | 59 | 0 | 10.6 |

- **arXiv が最大（23%）。** AI Scientist の出力形式と一致する
- **トップ会議の収録が少ない。** NeurIPS は実際には 2016–2018 で約 2,400 本あるはずが 171 本。
  `score_openalex >= 0.5`（ML では上位 7%）が厳しいか、AI タグ側に付いているため。
  **トップ会議だけでは約 620 本しか集まらず、POC の母集団にはできない**
- `score_openalex >= 0.5` でもノイズが残る（bioRxiv の生物応用、低品質ジャーナル）。
  平均被引用 10 前後が目印

### 2-3. 媒体情報は 70% しかない。`doctype` は全件ある

| 情報源 | カバー |
|---|---|
| `papers.doctype` | **100%** |
| `papersources`（媒体・version） | 15,653 / 22,302 = **70%** |

`papersources` は **1 論文 1 行**（`avg_locations = 1.0`、複数ロケーションを持つ論文は 0 件）。
OpenAlex の primary location だけを保持しているため、
**「arXiv 版と会議版の両方を持つ」という情報はこのテーブルから取れない**。

`version` 列の分布：

| version | 本数 |
|---|---:|
| `submittedVersion`（査読前） | 5,266 |
| `publishedVersion`（出版済み） | 3,819 |
| `acceptedVersion` | 104 |
| NULL | 6,464 |
| 行なし | 6,649 |

> **群分けの主軸は `doctype`**（全件ある）。`version` と媒体名は補助列として持たせるが、
> 欠損が 30% あるため群の定義には使わない。

### 2-4. 🚨 preprint には atypicality が存在しない

| 群 | 本数 | ベクトル作成可（過去≥5 ∧ 未来≥5） | atyp 比較可 |
|---|---:|---:|---:|
| `preprint` | 5,851 | **1,731** | **0** |
| `article` | 16,451 | **8,126** | 5,360 |

`Atyp_Median_Z` はジャーナルペアの Z-score なので、ジャーナルに載らない preprint では
**原理的に計算できない**。SciSciNet 側も全件 NULL にしている。

> **帰結：群A（preprint）では既存指標の比較対象が `disruption` のみになる。**
> atypicality を含む3指標の比較は群B（article）でしか成立しない。
> 第2章でこの非対称性を明記する必要がある。

preprint のベクトル作成可率が低い（29.6% 対 49.4%）のは参考文献数が少ないため（18.3 対 26.0）。

### 2-5. 同一研究の重複は 1.2%（軽微）

タイトル照合（+50GB）の代わりに**参考文献集合の Jaccard 係数**で検出した（44MB で済む）。
同じ研究の arXiv 版と会議版は参考文献がほぼ一致するため。

| 条件（参考文献 10 本以上の論文に限る） | ペア数 |
|---|---:|
| 共通参考文献 ≥ 10 | 7,762 |
| Jaccard ≥ 0.5 | 683 |
| **Jaccard ≥ 0.7** | **253** |
| Jaccard ≥ 0.9 | 44 |

Jaccard ≥ 0.7 の内訳：

| 組み合わせ | ペア数 | 同年 | 解釈 |
|---|---:|---:|---|
| `article` + `preprint` | **138** | 99 | **arXiv 版と会議版の統合漏れ** |
| `article` + `article` | 83 | 71 | 会議版とジャーナル拡張版など |
| `preprint` + `preprint` | 32 | 27 | arXiv 改訂版が別 ID になった等 |

> **当初の懸念（preprint が 22.8% なので大量重複か）は外れた。** 統合漏れは 276 本（1.2%）。
> OpenAlex が大半を 1 つの Work に統合済み（それが `papersources` 1 行の理由でもある）。
> ただし **群A/群B の比較では、`article` + `preprint` の 138 ペアは片方を落とす**
> （同じ研究が両群に入ると比較が汚れる）。

## 3. 群の定義

| 群 | 定義 | 本数（ベクトル作成可） | 比較できる既存指標 |
|---|---|---:|---|
| **A（査読前）** | `doctype = 'preprint'` | 1,731 | `disruption` のみ |
| **B（査読済み）** | `doctype = 'article'` | 8,126 | `disruption`・`Atyp_*` |

共通の条件（すべて `docs/pilot.md` に根拠）：

- ML（`C119857082`）、`score_openalex >= 0.5`
- `year BETWEEN 2016 AND 2018`、`is_retracted = FALSE`
- `has_text = TRUE`
- 過去ベクトル材料（埋め込みが取れる参考文献）≥ 5 本
- 未来ベクトル材料（5年窓の被引用、埋め込みが取れるもの）≥ 5 本

### 群間比較の注意

群A が 1,731 本しかないため、**公平な比較には群B から 1,731 本をサブサンプルする**。
層化は年（2016/2017/2018）で行う。群B 全体との比較は別途行う。

## 4. 実装要件

### 4-1. 中間テーブル `novelty_pilot.poc_dataset`

既存の 3 テーブル（`pilot_target_2016_2018` / `pilot_edges` / `pilot_neighbors`）から導出する。
`papersources` と `sources` のみ外部参照（約 5 GB）。それ以外は中間テーブルだけで無料。

| 列 | 内容 |
|---|---|
| `paperid` | 結合キー |
| `group_label` | `A_preprint` / `B_article` |
| `year`・`doctype`・`score_openalex` | 基本属性 |
| `reference_count`・`citation_count`・`C3`・`C5` | 引用関連 |
| `disruption`・`d_valid` | D-index（`d_valid` が false なら使わない） |
| `Atyp_Median_Z`・`Atyp_10pct_Z`・`Atyp_Pairs` | 非典型性（群A は全 NULL） |
| `team_size` | 著者数 |
| `n_ref_text` | 過去ベクトルの材料数（`year_diff >= 0` のみ） |
| `n_cit_text` | 未来ベクトルの材料数（5年窓） |
| `venue`・`version` | 媒体名と版（30% は NULL） |
| `is_dup_candidate` | Jaccard ≥ 0.7 のペアに含まれるか |
| `dup_partner` | 相手の `paperid`（複数なら 1 つ。デバッグ用） |
| `stage1_sample` | 段階 1 の 300 本サンプルに入るか |

### 4-2. サンプリングは再現可能にする

`RAND()` を使わない。実行するたびに結果が変わると、後で数値を追えなくなる。

```
ORDER BY FARM_FINGERPRINT(CONCAT(paperid, '<固定ソルト>'))
```

で疑似乱数の順序を作り、年ごとに上位 100 本（3 年 × 100 = 300 本）を取る。
ソルトは文書に書き残す。

### 4-3. 除外ルール（実装時に必ず入れる）

- [ ] 過去ベクトルは `year_diff >= 0` のエッジのみ使う（リーク対策。`docs/handover.md` §3-6）
- [ ] `has_text = FALSE` は除外（埋め込みが存在しない）
- [ ] `disruption` を使う行は `d_valid = TRUE` のみ（0 埋めバイアス。`docs/handover.md` §3-1）
- [ ] 群間比較では `article` + `preprint` の重複ペア（138 組）の片方を落とす
- [ ] 被引用は `citation_count`（`cited_by_count` ではない。`docs/handover.md` §3-3）

### 4-4. 検証項目

- [ ] 群A・群B の本数が §3 の数と一致するか
- [ ] 群A の `Atyp_Median_Z` が全 NULL であることを確認（§2-4 の再確認）
- [ ] `stage1_sample` が年ごとに 100 本ずつになっているか
- [ ] 同じ SQL を 2 回流して `stage1_sample` が変わらないか（再現性）

## 5. この先の判断ポイント

### 被引用数の偏りへの対処（未決）

被引用の分布は中央値 8・平均 45.1・最大 26,341（`docs/pilot.md`）。
未来ベクトルを単純平均で作ると、

- 被引用 8 本の論文：推定が不安定
- 上位 1%（595 本超）：安定するが平均が平凡な引用に埋もれる

**段階 1 の 300 本で、被引用数とベクトル距離の関係を見てから決める。**
候補：被引用数で層別する／対数重みを付ける／上位 N 本に切り詰める。

### トップ会議サブセット（将来）

NeurIPS・ICML・ICLR・AAAI・EMNLP で約 620 本。POC の母集団には小さすぎるが、
**第4章で「AI Scientist が目指す水準の論文」との比較が必要になったときに使える**。
媒体名は正規化されていない（`Neural Information Processing Systems` と
`neural information processing systems` が別 ID、CVPR は年ごとに別 ID）ため、
使うときは正規表現で拾い集める作業が必要。
