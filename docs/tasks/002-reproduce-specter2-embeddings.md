# Task 002: SciSciNet-v2 の SPECTER2 埋め込みを再現する

**担当：りけ（実装）／ Claude（ヒント・レビュー）**
ブランチ：`feat/step1-embedding-repro`

## 目的

2025 年以降の論文は SciSciNet-v2 に含まれないため、未来ベクトル（引用論文の埋め込み平均）を作るには、新しい論文の埋め込みを自分で計算する必要がある。
そのとき、**SciSciNet の埋め込みと同じ空間のベクトルを作れること**が前提になる。モデル・アダプタ・入力形式が少しでもずれると、「古い論文は SciSciNet、新しい論文は自前」の混在によって、実在しない「動き」が生まれ、第 2 章の指標が壊れる。

このタスクで次の 2 つを確定させる。

1. SciSciNet の埋め込みを再現できる設定（モデル・アダプタ・入力形式）
2. README の未決事項「SPECTER2（使用アダプタを要確認）」

## 分かっている事実（2026-09-22 確認）

| 項目 | 内容 |
|---|---|
| 置き場所 | `gs://sciscinet-neo/v2/embeddings/sciscinet_emb_chunk_0000.jsonl` 〜 `_0111.jsonl`（112 ファイル、計 1.62TiB） |

## ✅ 結論（2026-10-25）

**再現できる。設定は次の通り。**

```python
from transformers import AutoTokenizer
from adapters import AutoAdapterModel

tok = AutoTokenizer.from_pretrained("allenai/specter2_base")
model = AutoAdapterModel.from_pretrained("allenai/specter2_base")
model.load_adapter("allenai/specter2", source="hf", load_as="proximity", set_active=True)
model.eval()

text = title + tok.sep_token + abstract          # 要旨が無ければ title だけ
batch = tok([text], padding=True, truncation=True, return_tensors="pt", max_length=512)
vec = model(**batch).last_hidden_state[:, 0, :]  # CLS トークン
```

| 項目 | 確定した値 |
|---|---|
| モデル | `allenai/specter2_base` |
| アダプタ | **`allenai/specter2`（proximity）** ← README の未決事項の答え |
| 入力形式 | `title` + `[SEP]` + `abstract` |
| 文書ベクトル | 最終隠れ状態の **CLS トークン**（先頭） |
| 正規化 | しない（SciSciNet も未正規化） |

### 検証結果

| paperid | cos(SciSciNet, 自前) | 参照ノルム | 自前ノルム |
|---|---:|---:|---:|
| W583078353 | **0.996788** | 21.729 | 21.748 |
| W584426783 | **0.998718** | 21.884 | 21.885 |
| W574406607（中国語・要旨4語） | 0.998689 | 21.525 | 21.510 |

残差 0.3% 程度の原因候補：OpenAlex の現在の要旨が SciSciNet 作成時点と異なる、
`transformers` / `tokenizers` のバージョン差。実用上は同一空間として扱える。

### 注意：警告メッセージは誤解を招く

`load_adapter(..., set_active=True)` を使っても
`There are adapters available but none are activated for the forward pass.`

`set_active_adapters("proximity")` を追加で呼んでも出力は変わらない（不要）。

## ⚠️ コストの注意（必読）

- **埋め込みファイルを丸ごとダウンロードしない。** 1 ファイル約 16GB。全体をダウンロードすると転送料金が数万円規模になりうる
  - 先頭だけ読む：`gcloud storage cat -r 0-<バイト数> <ファイル>` でバイト範囲を指定できる。1 論文は約 15KB なので、300 本なら先頭約 5MB で足りる
- **BigQuery の `sciscinet_papertitleabstract` は 270GB。** パーティション分割されていないため、`WHERE paperid IN (...)` で 1 本に絞っても **270GB（月の無料枠の約 27%）をスキャンする**。このタスクでは使わない
  - タイトルと要旨は **OpenAlex API** から取る（下記の手順 2）。これは後の「2025 年以降の引用論文の取得」の予行演習も兼ねる

## やること

### 1. サンプルを取る

- [ ] 埋め込みファイルの先頭から論文を数百本分読み、`paperid` と `embedding` を保存する
- [ ] 1 つのファイルの先頭だけだと偏る可能性がある（ID 順、年代順など）。**2〜3 ファイルから少しずつ**取る
- 保存先：`data/embedding_repro/`（Git 管理外）

> ヒント：行の途中でバイト範囲が切れると、最後の行は壊れた JSON になる。どう扱うか考えること

### 2. タイトルと要旨を OpenAlex から取る

- [ ] 手順 1 の `paperid` について、OpenAlex API からタイトルと要旨を取得する
- [ ] 要旨は `abstract_inverted_index`（単語 → 出現位置のリスト）という形式で返ってくる。**元の文章に戻す関数**を書く
- [ ] 要旨がない論文、タイトルがない論文が何本あるかを数えておく（手順 4 で使う）

> ヒント：
> - API の利用条件（API キー、レート制限、`mailto` パラメータなど）は、**使う前に公式ドキュメントで確認する**。最近変わった可能性がある
> - 1 本ずつ取らずに、複数の ID をまとめて 1 回で問い合わせる方法がある（filter の OR 指定）
> - 注意：OpenAlex の今の要旨は、SciSciNet が作られた時点（2025 年頃）の要旨と違う可能性がある。一致しない場合の原因候補として覚えておく

### 3. SPECTER2 で埋め込みを計算する

- [ ] 依存関係を追加する：`uv add --package semantic-disruption ...`（CPU 版 PyTorch、`transformers`、`adapters`）
- [ ] 公式のモデルカード（Hugging Face の `allenai/specter2_base` と `allenai/specter2`）を読み、推奨されている使い方を確認する
- [ ] 次の設定の組み合わせで埋め込みを計算する

| 軸 | 候補 |
|---|---|
| モデル／アダプタ | ベースモデルのみ（`specter2_base`）、proximity アダプタ（`allenai/specter2`）、ほかのアダプタ（adhoc_query、classification、regression）、初代 SPECTER（`allenai/specter`） |
| 入力形式 | タイトル + `[SEP]` + 要旨、タイトルのみ、区切り方の違い |
| 最大長 | 512 トークンで切る、など |
| 取り出し方 | `[CLS]` トークンの出力、平均プーリング |

> ヒント：
> - いきなり全部を組み合わせない。**まず公式の推奨設定で 10 本だけ**計算し、手順 4 の比較まで一度通す
> - ノルムが約 21.5 という事実は、「正規化しない」「どの層の出力か」の手がかりになる
> - 乱数に依存しない処理だが、`model.eval()` と `torch.no_grad()` を忘れないこと

### 4. 比較する

- [ ] 各設定について、SciSciNet の埋め込みとのコサイン類似度を論文ごとに計算する
- [ ] 分布（最小値・中央値・下位 5%）を見る。**中央値 0.99 以上**を「再現できた」の目安にする
- [ ] ノルムの分布も SciSciNet と比べる
- [ ] 一致しない論文がある場合、要旨の有無、要旨の長さ（512 トークンを超えるか）、言語などで偏りがないか調べる

> 比較の基準として、**無関係な論文どうし**のコサイン類似度も計算しておく。HindSight の報告では、AI/ML の文書どうしでも 0.91〜0.98 と高く出るため、「0.95 なら一致」とは言えない

### 5. 処理速度を測る

- [ ] 手元の CPU で 1 秒あたり何本処理できるかを測る
- [ ] 100 万本を処理したら何時間かかるかを見積もる（Step 1 の計画に使う）
