# novelty-in-the-loop

> 非類似は新規ではない
> — 引用構造と内容埋め込みによる新規性の再定義と、研究エージェントへの組み込み位置の比較

**論文タイトル（案）：科学的新規性の事前評価と、その組み込み位置 ― 内容埋め込みに基づく新規性指標による研究エージェントの改善 ―**

---

## 1. 研究の概要

AI Scientist をはじめとする研究自動化システムの新規性判定は、「既存研究の中に似たものが見つからない＝新しい」という **非類似度** で新規性を代理している。しかし、非類似であることと新規であることは別物である。検索で近いものが見つからないのは、本当に新しいからかもしれないし、検索が外れただけかもしれないし、誰も価値を認めない方向に離れているだけかもしれない。

本研究は、SciSciNet-v2 の引用構造と SPECTER2 埋め込みを用いて、新規性を「その研究が何を土台にし、どこへ動いたか」として再定義する。そのうえで、この新規性をアイデア段階で予測する器を構築し、AI Scientist の新規性判定に組み込んで、判定がどう変わるかを検証する。

**一文で言うと：** 非類似度に頼る AI の新規性判定を、引用構造に基づく「動き」としての新規性で置き換え、その改善効果と原理的な限界を明らかにし、さらに **その評価器をエージェント系のどこに置くと最も効くか** を比較する。

### Research Questions

- **RQ1**：引用構造と内容埋め込みを用いて、「どこから、どこへ動いたか」としての新規性を測定できるか。それは既存指標（atypicality、D-index 等）と何が異なるか。
- **RQ2**：その新規性を、出版時点（アイデア時点）で観測可能な情報からどこまで予測できるか。予測の上限はどこにあるか。
- **RQ3（主）**：その予測器を AI Scientist の新規性判定・自動査読器に組み込むと、判定精度と生成されるアイデアの分布はどう変わるか。また、人間の査読者の事前判断と比べてどこに位置するか。
- **RQ4**：その評価器を、エージェント系の **どの位置**（アイデア生成時・候補選択時・自動査読時）に置くと最も効くか。配置によって、判定精度と生成アイデアの多様性のあいだにどのようなトレードオフが生じるか。

## 2. 中心的な考え方

### 非類似度と新規性の区別

| | 既存の新規性チェック | 本研究 |
|---|---|---|
| 基準 | 最も近い既存研究との距離 | 土台にした研究（被引用）と、そこから生まれた研究（引用）との関係 |
| 測っているもの | 非類似度 | 動き（どこから、どこへ） |
| 時間軸 | なし（現時点のスナップショット） | あり（出版前後） |
| 検証 | なし | 将来の実データで検証 |

本研究の指標も埋め込み空間の距離を用いるが、**距離の基準を引用構造と時間軸で定める** 点で、単なる非類似度とは異なる。

### 新規性の三分類（理論的背景）

| 種類 | 定義 | 測定可能な時点 |
|---|---|---|
| 素材の新規性 | 参考文献の非典型的な組み合わせ | 出版時（事前） |
| 内容の新規性 | 既存の知識空間からの意味的距離 | 出版時（事前） |
| 効果の新規性 | 出版後に分野の軌道が実際に変わったか | 事後のみ |

既存指標同士の相関がほぼゼロであることは、これらが異なる構成概念を測っていることで説明できる。

### 出版済みデータは新規性で切断されている

論文として発表されている時点で、その論文は査読による選別を受けている。つまり **出版済み論文は、新規性の下側の裾が落ちた母集団** である（統計的には range restriction）。

影響は 2 か所に出る。

- **第3章：** 目的変数の分散が圧縮されるため、予測精度は実際より低く出る。測れるのは無条件の天井ではなく **出版を条件づけた上での天井** である
- **第4章：** AI Scientist の生成アイデアはこの選別を通っていない。裾のあるデータに対して、裾の落ちたデータで学習した予測器を当てることになる

成否条件 ③（形式の頑健性）は入力分布のずれだが、こちらは **目的変数の分布そのもののずれ** であり、より本質的である。

### 掛け合わせとしてのイノベーション

イノベーションを「複数分野に跨った新規要素の掛け合わせ」と捉えるなら、**参考文献の埋め込みの平均は、その掛け合わせを消してしまう。**

1 分野を深く掘った論文と、離れた 2 分野を橋渡しした論文が、重心としては同じ位置に来うる。したがって過去ベクトル・未来ベクトルは、重心だけでなく **集合の散らばり** も持つ必要がある（意味空間版の atypicality に相当）。

とくに、過去の集合が複数の山に分かれ、未来の集合が 1 つにまとまる形は、**離れた分野を融合させた** signature であり、重心の移動距離だけを見ていては拾えない。

### 組み込みに予測器が必要な理由

事後の新規性指標は引用する側の論文を必要とするため、**生成されたばかりのアイデアには計算できない。** そこで、過去の論文で「出版時の特徴量 → その後の新規性」を学習した予測器を作り、それを AI Scientist のアイデアに適用する。第2章・第3章は、第4章の組み込みのための必須部品である。

## 3. 章構成

| 章 | 内容 | 役割 | 対応ステップ |
|---|---|---|---|
| 第1章 | 問題設定：非類似度≠新規性。AI Scientist の新規性判定の脆弱性 | 動機 | Step 0 |
| 第2章 | 事後の新規性指標の構築（引用構造 × 埋め込み） | 正解ラベルを作る | Step 2 |
| 第3章 | 事前予測器の構築と予測上限の測定 | 組み込む部品を作る | Step 3 |
| 第4章 | AI Scientist への組み込みと評価 | **主役** | Step 4 |
| 第5章 | 組み込み位置の比較（アーキテクチャの ablation） | 配置の設計指針 | Step 5 |

第3章の予測上限は、第4章の改善幅の天井として、結果の解釈を支える。

### 研究の成否を分ける条件（目的からの逆算）

主張できるのは B → C の改善のみである。これが成り立つには、次の 4 つが順に成り立つ必要がある。

| | 成り立つべきこと | 章 | LLM | カットオフの影響 |
|---|---|---|---|---|
| ① | 「動き」の指標が妥当で、最近傍距離（非類似度）とは別物である | 第2章 | 使わない | なし |
| ② | その「動き」を、出版時点のテキストから B より良く予測できる | 第3章 | 使わない | なし |
| ③ | 論文要旨で学習した予測器が、AI の生成アイデアの文章にも通用する | 第3〜4章 | 一部 | 小さい |
| ④ | AI Scientist に組み込むと、元の判定（A）より良くなる | 第4章 | 使う | **ここだけ** |
| ⑤ | 配置による差が、LLM の確率的なばらつきを超えて観測できる | 第5章 | 使う | ④ と同じ |

- **ボトルネックは ②。** ② が成り立たなければ、第4章の環境をどれだけ整えても C は B に勝てない。一方で ② は SciSciNet だけで安く早く確かめられるため、**Step 1.5 のパイロットで最初に検証する**
- ① と ② は LLM を使わないので、古い時点（例：2012〜2015 年）で長い引用窓を取って検証できる。LLM の知識カットオフの制約を受けない
- カットオフの制約を強く受けるのは 4-1 と 4-2 のみ。4-3（正解は OpenReview の採択判定）と 4-4（人間・C は記憶を持たない）は影響が小さい
- リークは A を有利にする方向に働くため、古い時点で A を評価しても C が勝てば主張はむしろ強まる

### Step 2：事後の新規性指標の構築 ＝ 第2章

- [ ] 過去ベクトル：被引用論文の埋め込みの平均
- [ ] 未来ベクトル：引用論文の埋め込みの平均
- [ ] 両者の関係から「動き」としての新規性を算出
- [ ] 重心に加えて **集合の散らばり** を特徴量に含める（分散、最大ペア間距離、クラスタ数）
- [ ] 融合 signature（過去が複数クラスタ → 未来が単一クラスタ）を定義し、重心移動と独立に効くかを検証
- [ ] 既存指標（D-index、CD index、atypicality）との比較
- [ ] 最近傍距離（既存の新規性チェックに相当）との比較：非類似度と何が違うかを示す
- [ ] 妥当性の検討（引用数の少ない論文、引用窓の長さ）
- [ ] **測定の限界として書く：素材の新規性には粒度が2つあり、本研究は語彙レベルを測っていない**
  - 書誌レベル（参考文献・ジャーナルの組み合わせ）＝ `Atyp_*`。測れている
  - **語彙レベル（タイトル・要旨の語の組み合わせ）＝ 測っていない**
  - 例：「医療分野における、CT 画像の、リッジ回帰による画像検知」。構成要素はすべて既知で
    新しいのは組み合わせだけ。**埋め込みは文全体の意味を平均化するため、
    この掛け合わせは「医療画像」の密集領域に落ちて消える**
  - 散らばり・分離度が捉えるのは**論文間**の組み合わせ（参考文献集合が複数の山に分かれるか）。
    **論文内**の語の組み合わせは別物で、参考文献が同一分野に集まっていれば分離度も低く出る
  - この例は三分類の実例でもある：① 素材（語彙レベル）は高い／② 内容は低い／③ 効果は低い。
    **① が高くても ③ が低い**ことの分かりやすい証拠として第1章で使える
  - 語彙レベルを特徴量に足すかは Kim et al.（2025）EDM を読んでから判断する（**現状は限界として書くだけ**）

**成果物：** 指標算出コード、第2章草稿

### Step 3：事前予測器の構築 ＝ 第3章

- [ ] 時点 t で観測可能な特徴量を定義
  - 素材の新規性（atypicality 等）
  - 内容の新規性（t 時点の知識空間からの距離）
  - **アイデアのテキストだけから計算できる特徴量**（AI Scientist への適用のため必須）
- [ ] t 以降の新規性（Step 2 の指標）を予測するモデルを構築
- [ ] 予測性能の上限を定量化（複数時点で頑健性を確認）
- [ ] Impact4Cast 型のベースラインと比較（ネットワーク特徴量のみのモデル。時点分割は相手の設計を借用：y の特徴量 → y+3 のラベル、特徴量は y, y−1, y−2 のみ）
- [ ] **同じデータで「被引用の二値分類」も解き、AUC で並べる。** 相手の AUC 0.95 と本研究の Spearman 0.19 は指標が違うため直接比較できない。同じ土俵で並べれば「被引用は予測しやすいが破壊性は予測しにくい」を実証でき、新規性の三分類の裏づけになる
- [ ] **③ の検証（形式の頑健性）：** 実在論文の要旨を AI Scientist のアイデア形式（題名・仮説・手法など）に書き換えて予測器に通し、元の要旨での予測とどれだけ一致するかを見る（生成アイデアには将来がなく直接検証できないため）

> **注意：** 第4章で使うのは「アイデアのテキストだけから計算できる特徴量」に限った予測器である。論文の書誌情報（著者、掲載先など）は、生成アイデアには存在しない。

> **主張の範囲（母集団の切断）：** 学習データは出版済み論文であり、査読による選別を受けている。したがって本章が測るのは **出版を条件づけた上での予測上限** である。主張は次のように限定して書く。
>
> - ❌ 事前情報では効果の新規性を予測できない
> - ⭕️ **すでに新規性で選別された母集団の中では、事前情報による更なる弁別が難しい**
>
> 弱い主張になるのではなく、正確な主張になる。

**成果物：** 予測器、第3章草稿

### Step 4：AI Scientist への組み込みと評価 ＝ 第4章（主役）

**スコープ：** AI Scientist のうち、アイデア生成と新規性チェックのみを使用する。実験の実行と論文執筆は回さない（GPU 不要、LLM API コストのみ）。

**比較する 3 条件（第4章全体で共通）**

| 条件 | 手法 | 測るもの |
|---|---|---|
| A | 元の新規性チェック（Semantic Scholar 検索 + LLM 判断） | ベースライン |
| B | SPECTER2 の最近傍距離（SciSciNet-v2 の大規模コーパス） | 検索を良くしただけの効果 |
| C | 提案手法（「動き」としての新規性の予測器） | 本研究の主張の効果 |

- A → B の改善は「検索の網羅性の改善」、**B → C の改善が「非類似度から動きへの転換」の効果** であり、本研究が主張できるのは B → C の部分である
- Beel らの事例（マイクロバッチ化の誤判定）の主因は、似たものを見つけられなかった検索の再現率の低さであり、B で大きく改善しうる。したがって C の価値は「焼き直しではないアイデアの中で、どれが分野を動かすかを区別できるか」で示す
- **母集団のずれ（要検討）：** 予測器は出版済み論文で学習するが、生成アイデアは査読の選別を通っていない。下側の裾に対する挙動が未検証のまま残る。下側の裾の代理として OpenReview の **不採択論文**（全文・査読スコア・採否が揃い、分野も ML で一致）を使えるかを第4章の設計時に判断する。効果の新規性をどう定義するか（引用窓が短い、arXiv 版の引用を追う等）が論点
- A は v1 の `check_idea_novelty`（`ai_scientist/generate_ideas.py`）を使う。v2 は新規性確認がアイデア生成ループ（`perform_ideation_temp_free.py`、行動は SearchSemanticScholar / FinalizeIdea の 2 つ）に溶け込んでおり、外部のアイデアを判定する独立した部品がないため、4-1・4-3 には使えない。v2 は第1章と 4-2 の補足に留める
- 使用するコミットハッシュを固定し、README に記録する（`vendor/` に git submodule として置く）

**条件 A の実装上の事実（v1 のコードで確認）**

- 埋め込みやコサイン類似度は使っていない。LLM が検索クエリを書き、Semantic Scholar の上位 10 件の要旨を読んで「大きく重なるか」を主観的に判断する（最大 10 ラウンド）
- 判定は、LLM の出力に "Decision made: novel." / "not novel." という文字列が含まれるかで決まる。10 ラウンドで決まらなければ `novel = False`
- 検索クエリは「論文名や著者を思い出せると最もうまく働く」と指示されており、**検索の質が LLM の記憶に依存する** → 4-5 の記憶の分析は必須
- 出力は二値のみ → 同じアイデアを複数回判定させ、「新規と判定された割合」を連続スコアとして使う
- システムプロンプトにテンプレートの `experiment.py` が丸ごと入る → 評価セット（実在論文由来）には、コードなし・分野説明のみの中立的な文脈を用意し、公平性のための改変として明記する
- 検索エンジンは Semantic Scholar と OpenAlex を切り替えられる → OpenAlex を使えば SciSciNet-v2 と同じ論文の宇宙で A / B / C を比較でき、時点 t での検索制限も出版年フィルタで書ける
- B・C は `check_idea_novelty(ideas, ...)` と同じ入出力の関数として実装し、二値ラベルに加えて連続スコアも返す
- （ローカルのコードで追加確認）生成時の自己評価スコア（Novelty 1–10 など）が idea の dict ごと判定プロンプトに入る。検索結果には**現在の**被引用数が表示される（v2 はさらに被引用数の降順に並べ替える）。いずれも時点 t の評価では事後情報のリークになるため、公平性のための改変の対象とする
- （同上）例外は握りつぶされてラウンドを消費し、10 ラウンドを使い切ると `novel = False` になる → API 障害が「新規でない」に化けるため、失敗ラウンド数をログで集計する
- 詳細（行番号付き）は `docs/ai-scientist-notes.md`

**4-1. 判定精度の検証**

- [ ] 時点 t で切ったデータで評価セットを作成
  - 対象は ML 分野（Step 1.5 と同じ定義）。AI Scientist のアイデアは計算機上で検証できる実証的な ML に偏るため、理論中心の論文を除くことも検討する（CS 全般から作ると比較が不公平になる）
  - t 以降に実際に分野を動かした論文のアイデア
  - 既存研究の焼き直し
- [ ] A / B / C で分類精度を比較
- [ ] 評価を 2 段に分ける
  - 焼き直しを見抜けるか（既知 vs 新規）：A → B の改善が主に効くと予想
  - 新規なものの中で、分野を動かしたものを見分けられるか：B → C の改善が問われる
- [ ] 既知の失敗事例（例：SGD のマイクロバッチ化を新規と誤判定）の再現と、A / B / C それぞれでの判定

**4-2. 生成への効果**

- [ ] 新規性フィルタを A / B / C に差し替えてアイデアを生成
- [ ] 生成アイデアの分布を 3 つの軸で評価し、食い違いを分析
  - 将来論文との一致（HindSight 型）
  - 提案手法による新規性予測
  - LLM-as-Judge

**4-3. 自動査読器（Automated Reviewer）の改良としての検証**

AI Scientist 自身が査読器の検証に用いた枠組みに乗る。正解ラベル・人間の基準・汚染対策の設計を、彼らと同じ土俵で借りる。

- [ ] OpenReview の ICLR 論文と人間の採択判定を取得（正解ラベル）
- [ ] 既存の Automated Reviewer（5 本のアンサンブル + メタレビュー）をベースラインとして再現
- [ ] B（最近傍距離）と C（提案手法の新規性予測）をそれぞれ査読器の入力に加え、人間の採択判定との一致度（balanced accuracy、F1、AUC）の変化を測る
- [ ] 人間同士の一致度（NeurIPS 2021 一貫性実験）を天井として比較
- [ ] 汚染対策：学習データに含まれうる年の論文と、学習カットオフ後の「クリーンな」年の論文で分けて評価（Nature 版の設計に倣う）

> **注意：** 採択判定は新規性そのものではなく、健全性・書き方・流行を含む総合判断である。一致度が上がっても新規性の寄与かどうかは切り分けが必要（4-4 で補う）。

**4-4. 人間・AI・事後結果の三角比較**

OpenReview の人間の査読に含まれる貢献度（contribution）・新規性のスコアを、**出版前の時点で人間の専門家が下した新規性の判断** として扱う。

- [ ] 次の 3 つの関係を比較する
  - 人間の事前判断（査読者の貢献度スコア）
  - AI の事前判断（A / B / C）
  - 事後の結果（第2章の新規性指標）
- [ ] 「人間の専門家でも事前にどこまで当てられるか」を示し、第3章の予測上限を人間との比較で位置づける
- [ ] 提案手法が人間の事前判断と事後の結果のどちらに近いかを分析する

**4-1・4-2 の時点と引用窓（カットオフ問題）**

データは実質 2024 年まで。カットオフ後の時点 t（例：2023 年末）で十分な引用窓を取るには、2025〜2026 年の引用を OpenAlex から補う必要がある。その場合、引用関係に加えて **引用した側の論文の埋め込み** も必要になる（未来ベクトルの計算のため）。

- [ ] （Step 1.5 で見込みがあれば）OpenAlex から、対象論文を引用した 2024〜2026 年の論文の ID・出版日・タイトル・要旨を取得（API かスナップショットか。利用条件は公式ドキュメントで確認）
- [ ] SPECTER2 の埋め込みを自前で計算
- [x] **埋め込みの再現検証（2026-10-25、完了）：ML 論文 18,698 本で cos 平均 0.9979（cos >= 0.99 が 97.46%）。** SciSciNet の埋め込みと自前計算は同一空間として扱える（`docs/tasks/002-reproduce-specter2-embeddings.md`）
- [ ] 直近数か月は OpenAlex への登録が遅れるため、引用窓の終わりに余裕を持たせる
- 例：GPT-4o（知識カットオフ 2023 年 10 月）で t = 2023 年末なら、2026 年までで約 2.5〜3 年の引用窓（C3 と比較可能）

これは 4-1・4-2 を完全な形で行うための投資であり、研究の前提条件ではない。

**4-5. リーク対策（必須）**

- [ ] 使用 LLM の知識カットオフから t を設定
- [ ] Semantic Scholar 検索を t 以前に制限（比較の公平性のための改変として明記）
- [ ] プローブ：t 以降の論文をモデルが知っているかを直接検査
- [ ] 既知の論文を除外した部分集合でも結論が変わらないことを確認
- [ ] **（必須）** 記憶の有無で条件 A の精度が変わるかを分析（A は検索クエリ自体が LLM の記憶に依存するため。「LLM は新規性を判断しているのか、知っているかを答えているのか」）

**4-6. 生成アイデアが意味空間のどこに落ちるか（失敗の型の説明）**

条件 A・B の失敗を「精度が低い」ではなく **失敗の型** として説明する。
追加のデータ取得は不要で、Step 1.5 で整備した埋め込みをそのまま使う。

生成アイデアを SPECTER2 で埋め込み、既存研究の密度に対する位置で分類する。

| 落ちた位置 | 解釈 | A・B はどう判定するか |
|---|---|---|
| 既存研究の**密集領域の内側** | 焼き直し | 正しく「新規でない」と判定できる |
| 密集領域の**縁** | **有望** | B は弾いてしまう（近い論文があるため） |
| **完全な空白** | 多くは実行不可能・無価値 | **A・B は「新規」と判定する ← 失敗の型** |

> **狙い：** 「空間が空いている ≠ 研究の余白」である（第1章の論法の空間版）。
> 空白には (a) 未開拓で有望・(b) 不可能または無価値・(c) 言語化されないだけ の3種類があり、
> 非類似度に頼る A・B は (b)(c) を (a) と区別できない。
> **条件 C がそれを弾けることを示せれば、第4章の主張が「精度が上がった」から
> 「AI の新規性判定の失敗の型を説明できた」に強まる。**

- [ ] 生成アイデアの埋め込みに対し、既存研究コーパスでの局所密度（k 近傍距離・カーネル密度）を算出
- [ ] 「密集／縁／空白」の 3 区分を、閾値ではなく分位点で定義する（絶対距離は分野で意味が変わるため）
- [ ] 区分ごとに A・B・C の判定を集計し、**空白に落ちたアイデアで A・B が「新規」と判定する率**を見る
- [ ] 空白に落ちたアイデアを人手で読み、実行不可能・無価値かを確認（n は小さくてよい。事例として提示する）

⚠️ **やらないこと：** 意味空間の空白そのものを「研究の余白」として予測する分析は、
**この修論では扱わない**（Future Work）。768 次元では大半の領域が空であり、
3 次元への射影で見える空白は射影のアーティファクトになりうる。
空白の有望さを検証するには「過去の空白が後に埋まったか」の時点分割分析が必要で、
それ自体が独立した研究になる。本節は**空白を予測に使うのではなく、
A・B の失敗を説明するために使う**。

**成果物：** 第4章草稿

### Step 5：組み込み位置の比較 ＝ 第5章

**目的：** 第4章で有効性が示された評価器（条件 C）を、エージェント系の異なる位置に置いて比較する。**新しいアーキテクチャを設計するのではなく、同一の評価器の配置を変える ablation として定義する。** これにより第4章の評価基盤をそのまま再利用でき、比較の軸が1つに絞られる。

**比較する 3 配置**

| 配置 | 介入点 | 期待される効果 | 想定される副作用 |
|---|---|---|---|
| P1 生成時 | アイデア生成のプロンプト／条件づけ | 探索の方向を変える | 多様性の低下、指標への過適合 |
| P2 選択時 | 生成された候補群のランキング | 生成を変えずに選別を改善 | 生成されなかったものは選べない |
| P3 査読時 | Automated Reviewer の判定 | 下流での品質管理 | 上流の分布は変わらない |

- [ ] 各配置を実装（評価器は第4章の C を共通で使う。配置以外の条件は揃える）
- [ ] 評価は第4章と共通：OpenReview の採択判定との一致、人間の貢献度スコアとの比較
- [ ] **生成アイデアの分布も測る**（配置によって精度と多様性のトレードオフが変わるため。精度だけ見ると P1 を過大評価しうる）
- [ ] 併用（P2＋P3 など）が単独より効くかを確認

**統計上の要件（成否条件 ⑤）**

LLM の出力は確率的であり、**1 配置 1 回の実行では差を主張できない。** 実行前に次を決めて記録する。

- [ ] 各配置あたりのシード数（最低 3、できれば 5）
- [ ] 1 回あたりの生成アイデア数
- [ ] 差の検定方法と、報告する効果量
- [ ] 上記から見積もった API コストの上限

**判断基準：** 配置間に差が出ない場合も結果である。「評価器の効果は配置に依存しない」は、実装者にとって有用な知見として報告する。

### データの扱い

- 全量ダウンロードはしない。重い処理は BigQuery で済ませ、絞り込んだ結果のみ手元に降ろす
- 配布元データは更新されうるため、絞り込んだ結果を自分のバケットに固定し、抽出日を記録する
- 予算アラートを設定済みであること

### 再現性のルール

- データとコードを厳密に分離する（`data/` は Git 管理外）
- SQL（DDL を含む）は再現性の成果物としてコミットする
- 抽出条件（分野、期間、t、フィルタ）は設定ファイルにまとめ、コードに直書きしない
- 乱数シードを固定する

## 8. リスクと対策

| リスク | 対策 |
|---|---|
| HindSight と被る | 評価軸（破壊性）、予測上限、判定モジュールの差し替えの 3 点で差別化。HindSight は評価手段として借りる |
| 予測上限が低く、第4章の改善が小さい | 「事前判定の原理的な限界と、AI Scientist の判定がその中のどこにいるか」という診断として問いを立てておく |
| 提案指標も距離であり、「非類似度と何が違うのか」と問われる | 距離の基準を引用構造と時間軸で定める点を明示し、最近傍距離との比較を Step 2 で必ず行う |
| アイデアに書誌情報がなく、予測器が使えない | Step 3 で、テキストのみから計算できる特徴量に限った予測器を用意する |
| LLM への将来情報のリーク | カットオフで t を設定、プローブ、除外分析。リークは比較相手に有利に働くことを明示 |
| 改善が「検索が良くなっただけ」と見なされる | A / B / C の 3 条件比較で、検索の改善（A→B）と新規性の再定義の効果（B→C）を切り分ける |
| 採択判定の一致度向上が新規性の寄与か判別できない | 4-4 で人間の貢献度スコアと事後指標との三角比較を行い切り分ける |
| OpenReview 論文が SciSciNet-v2 と照合できない | Step 1 で照合率を早期に確認。低ければ OpenAlex 経由の照合やタイトル一致で補う |
| AI Scientist のライセンス上の義務（AI 使用の開示など）を見落とす | v1 / v2 の LICENSE を実物で確認し、指導教員と共有する |
| テキストから「動き」を予測できず、C が B に勝てない（成否条件 ②） | Step 1.5 のパイロットで最初に検証し、早い段階で問いを調整できるようにする |
| 論文要旨で学習した予測器が生成アイデアに通用しない（成否条件 ③） | 要旨をアイデア形式に書き換えて予測の一致度を確かめる |
| 自前で計算した埋め込みが SciSciNet の埋め込みとずれ、ニセの「動き」が生じる | 自前計算の前に数百本で再現検証（コサイン類似度 ≈ 1.0）を行う |
| データが実質 2024 年までで、カットオフ後の t に十分な引用窓が取れない | ①② は古い時点で検証。4-1・4-2 のみ OpenAlex で補完する |
| 埋め込みの取り出しで転送料・スキャン料が膨らむ | US リージョンの VM で一度だけ走査して抜き出し、索引を作る |
| 母集団の切断：出版済み論文は新規性で選別されており、予測上限を過小評価する | 第3章の主張を「選別後の母集団の中での弁別可能性」に限定して書く |
| 生成アイデアは選別を通っておらず、学習データと母集団がずれる | OpenReview の不採択論文を下側の裾の代理として使えるか第4章で検討する |
| 配置間の差が LLM のばらつきに埋もれる（成否条件 ⑤） | 実行前にシード数・検定方法・効果量を決めて記録する。差が出ないことも結果として報告する |
| 第5章が肥大化し、第4章までが疎かになる | 第5章は既存アーキテクチャ上の配置 ablation に限定する。新アーキテクチャの設計は今後の課題に置く |
| スコープの拡大 | 実験実行・論文執筆・マルチエージェント進化は今後の課題に置く |
